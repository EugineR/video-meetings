# Ralph Loop — как пользоваться

Короткий гайд для разработчика.

> Устройство и обоснование решений — в [plan.md](./plan.md).

---

## Что он делает

Берёт открытые issue из milestone фазы, реализует их по одной — каждую отдельной сессией
Claude, — коммитит в ветку фазы, прогоняет авто-ревью, вливает фазу в фича-ветку
отдельным merge-коммитом с тегом. Затем переходит к следующей фазе. Когда фазы кончатся —
открывает **один PR** в `master` и останавливается.

```
одна issue  = одна сессия
одна фаза   = один merge-коммит с тегом на фича-ветке = точка отката
вся фича    = один PR, который мержите вы
```

**В `master` оркестратор не пишет ничего.**

---

## Перед первым запуском

```bash
docker compose up -d postgres     # e2e-тесты бьют в реальную БД
gh auth status                    # оркестратор ходит в GitHub через gh
```

В `.claude/ralph.config.json` должны быть перечислены фазы (`milestone` + `branch`),
а на GitHub — соответствующие milestone с issue. Бэклог создаётся скиллом `/issues`
из `docs/<фича>/plan.md`.

## Типичный сеанс

### 1. Посмотреть, что предстоит и во сколько обойдётся

```bash
node .claude/ralph-start.js --dry-run
```

```
Целевая ветка: master
Оценка: 1.80M на issue (базовая линия, статистики пока нет)

  ⏭ Phase 1: Profile read & display name API (Tracer Bullet) — уже завершена
   5 issue  ~13.00M вх  ≤ 13 сессий   Phase 2: Password change API
   5 issue  ~13.00M вх  ≤ 13 сессий   Phase 3: Avatar storage & upload/delete API
   2 issue  ~ 7.60M вх  ≤  7 сессий   Phase 6: Profile page
   ...

Итого: 7 фаз, 32 issue, ~85.60M входных токенов, максимум 85 сессий
```

Ни одна сессия не запускается — только оценка.

### 2. Запустить столько фаз, на сколько не жалко лимита

```bash
node .claude/ralph-start.js --phases 2
```

Уже закрытые фазы пропускаются автоматически и в счёт `--phases` не идут.

### 3. Наблюдать

```

[14:26:30] ✓ issue #31 закрыт · 24 турна · 1.9M вх · 3м25с · completed · всего за прогон 1.9M
[14:41:02] ▶ ревью фазы · раунд 1/3 · opus
[14:44:10]   ревью: APPROVED · 31 турн · 2.4M вх · 3м08с
```

Если из сессии больше 2 минут не приходит событий — появится предупреждение. Если тишина
затянется, сессия будет убита и пойдёт повторная попытка.

### 4. Забрать результат

```bash
git log --first-parent --oneline feature/user-profile   # фазы
git log --oneline feature/user-profile                 # issue внутри фаз
git tag -l "ralph/phase-*"                             # точки отката
```

## Флаги

| Флаг              | Что делает                                                                          |
| ----------------- | ----------------------------------------------------------------------------------- |
| `--dry-run`       | показать состав и оценку расхода, ничего не запуская                                |
| `--phases N`      | выполнить максимум N фаз и остановиться                                             |
| `--only <n\|имя>` | выполнить ровно одну фазу (аварийный люк — предупредит, если пропускает незакрытые) |
| `--issues N`      | остановиться после N закрытых issue, даже посреди фазы                              |
| `--branch <имя>`  | переопределить ветку фазы; только вместе с `--only`                                 |
| `--stop-on-limit` | при упоре в rate limit остановиться, а не ждать сброса окна                         |

Без флагов выполняются все незакрытые фазы из конфига.

## Как остановить

| Способ                     | Что произойдёт                                                        |
| -------------------------- | --------------------------------------------------------------------- |
| **Ctrl-C** один раз        | текущая сессия доигрывает, следующая issue не берётся                 |
| **Ctrl-C** дважды          | сессия убивается немедленно                                           |
| `touch .claude/ralph.stop` | проверяется между сессиями — если вас нет у терминала (ночной прогон) |

Прерывать безопасно. Коммиты останутся на ветке фазы, закрытые issue — закрытыми,
**ничего не смержится**, если фаза не дошла до конца. Повторный запуск продолжит с той же
точки: закрытые issue пропустит, ветку переиспользует, PR не продублирует.

## Цикл встал — что дальше

| Сообщение                  | Что делать                                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `issue #N не продвигается` | посмотреть последние сессии в `ralph.log` и комментарии в issue; чаще всего задача сформулирована неоднозначно |
| `issue #N вышла за бюджет` | issue слишком крупная — разбить на две                                                                         |
| `фаза не проходит ревью`   | ветка фазы не влита, follow-up issue заведены; прочитать их и решить, чинить или закрыть                       |
| `нужно разрешение X`       | добавить в `permissions.allow` в `.claude/settings.json` и перезапустить                                       |
| `ветка отстала от base`    | разрешить конфликт вручную в ветке фазы, затем перезапустить                                                   |
| `тесты красные`            | `pnpm lint && pnpm test` локально, починить, перезапустить                                                     |

Во всех случаях перезапуск — та же команда, что и в начале. Оркестратор сам разберётся,
что уже сделано.

## Где смотреть, что было

Два файла, оба в `.gitignore`:

- **`.claude/ralph.log`** — точная копия консольного вывода. Читать глазами: что происходило и на чём встало.
- **`.claude/ralph.stats.jsonl`** — по строке JSON на сессию (`kind`, `phase`, `issue`, `terminalReason`, `turns`, `inputTokens`, `outputTokens`, `costUsd`, `durationMs`). Отсюда берётся медиана для `--dry-run`.

Расход по фазам:

```bash
jq -s 'group_by(.phase) | map({phase: .[0].phase, tokens: (map(.inputTokens) | add), cost: (map(.costUsd) | add)})' .claude/ralph.stats.jsonl
```

## Откат фазы

Пока фича не в `master`, каждая фаза — merge-коммит с тегом на фича-ветке:

```bash
git switch feature/user-profile
git reset --hard ralph/phase-4        # вернуться к состоянию после фазы 4
git push --force-with-lease           # если ветка уже запушена
```

Либо откатить одну фазу, сохранив историю:

```bash
git revert -m 1 <merge-коммит фазы>
```

После этого переоткройте issue отката и запустите цикл снова — он увидит их открытыми.

## Частые грабли

- **Не редактируйте `phases` в конфиге, чтобы ограничить прогон** — для этого есть `--phases`. Именно так из каталога однажды пропали 7 фаз.
- **Не поднимайте `maxTurns` «на всякий случай».** 100 — это уже двойной запас к фактическим 28–42 турнам. 500 разрешает одной сессии выбрать всё пятичасовое окно.
- **`/model opus` в интерактивной сессии на цикл не влияет** — модели заданы в конфиге явно (`implModel`, `reviewModel`). Это сделано специально: раньше цикл молча наследовал интерактивный дефолт и работал вдвое дороже.
- **Оркестратор никогда не мержит в `master`.** Финальный PR остаётся открытым до вашего решения; мержьте **merge-коммитом, не squash**, иначе история по issue схлопнется.
- **Одна фича за раз.** Параллельные прогоны упираются в общий рабочий каталог, общую БД и общий rate limit — см. §12 в [plan.md](./plan.md).
